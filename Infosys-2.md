🚀 **Infosys Interview Experience | Java | Spring Boot | Microservices | Kafka**  
I recently attended an interview with **Infosys** for a **Senior Java / Spring Boot / Microservices** role.  
The interview was mainly focused on **real-world scenarios, scalability, performance, fault tolerance, distributed systems, and system design** rather than only theoretical concepts.  
🔹 Questions Asked  
**Java / Design Principles**  
Explain **SOLID principles** with real-world examples.  
**Spring Boot / Hibernate**  
What is the **N+1 problem** in Hibernate?  
How do you identify and resolve the N+1 problem?  
How would you handle **5 lakh records efficiently**?  
How would you optimize a **slow API**?  
**Kafka**  
What is a **Kafka Topic**?  
How does Kafka handle high-volume data?  
What are partitions and consumer groups?  
How do you handle failed Kafka messages?  
**Microservices / System Design**  
How would you design **Payment, Inventory, and Notification services**?  
What happens if the **Payment Service goes down**?  
What happens if **Payment succeeds but Inventory Service fails**?  
What happens if the **Notification Service is unavailable**?  
How do you handle **distributed transactions**?  
What is the **Saga Pattern**?  
What is a **Circuit Breaker**?  
How would you handle **retries and timeouts** between microservices?  
How do you implement **Idempotency** in payment processing?  
**SQL Server**  
What is a **Stored Procedure**?  
Why would you use a Stored Procedure?  
How would you optimize SQL queries for a large dataset?  
**CI/CD**  
What is **CI/CD**?  
Explain a CI/CD pipeline for a **Spring Boot application**.  
What happens if **unit tests fail** during the pipeline?  
How would you handle a failed production deployment?  
**Docker**  
How do you **Dockerize a Spring Boot application**?  
What is a **Dockerfile**?  
What is the difference between a Docker image and a container?  
How would you configure Spring Boot services using **Docker Compose**?  
💡 Key Takeaway  
The interview was not limited to theoretical questions. The interviewer focused heavily on **how we would handle real production scenarios**, especially:  
🔹 **Scalability** → 5 lakh records  
🔹 **Performance** → N+1 / Indexing / Pagination / Caching  
🔹 **Messaging** → Kafka / Topics / Partitions / Consumer Groups  
🔹 **Reliability** → Retry / Circuit Breaker / Idempotency  
🔹 **Distributed Transactions** → Saga / Compensation  
🔹 **Database** → Stored Procedures / Query Optimization  
🔹 **DevOps** → Docker / CI/CD / Deployment  
Overall, it was a good experience and a strong reminder that **real-world problem solving and system design are just as important as knowing the technology itself.**
